# Учёт студентов

Учебный фронтенд к [бэкенду преподавателя](https://github.com/dorzhogun/fun-student).

Автор: Маслова Варвара.

Написан на обычных **HTML, CSS и JavaScript**. Vite нужен только для запуска локального сервера и перенаправления запросов к бэкенду.

## Что сделано

- Вход по email и паролю — аутентификация.
- Доступ к страницам и кнопкам в зависимости от роли — авторизация.
- Получение JWT от бэкенда и передача его в заголовке `Authorization: Bearer ...`.
- Сохранение сеанса в текущей вкладке, выход и завершение сеанса при истечении токена или ответе 401.
- Просмотр студентов и их контактов.
- Добавление, изменение контактов и удаление студентов для администратора.
- Просмотр, создание и удаление пользователей для суперадминистратора.

Проверку пароля, подписи JWT и прав доступа выполняет бэкенд. Фронтенд обращается к его API. Публичной регистрации в исходном бэкенде нет: учётные записи создаёт суперадминистратор.

## Запуск

Нужны Node.js 22.12+ (рекомендуется 24), Java 21 и PostgreSQL.

**1. Запустить бэкенд преподавателя.**

Скачать [fun-student](https://github.com/dorzhogun/fun-student). Создать в PostgreSQL базу `students_db` и схему `students_schema`. По исходному `application.yml` подключение идёт на `localhost:5432`, пользователь `postgres`, пароль `postgres`. При других настройках изменить конфигурацию бэкенда.

В папке бэкенда на macOS / Linux:

```bash
chmod +x mvnw
./mvnw spring-boot:run
```

На Windows:

```powershell
.\mvnw.cmd spring-boot:run
```

**2. Запустить этот фронтенд.**

Открыть терминал в папке фронтенда:

```bash
npm ci
npm run dev
```

Открыть адрес, напечатанный Vite, обычно `http://localhost:5173`.

Бэкенд должен работать на `http://localhost:8080`. Vite перенаправляет к нему запросы `/api`, поэтому для локального запуска не нужно изменять CORS в Spring Security. Если адрес другой, скопировать `.env.example` в `.env`, изменить `BACKEND_URL` и перезапустить фронтенд.

## Учебные аккаунты

Эти данные взяты из `AppInitializer` бэкенда. При первом запуске он создаёт аккаунты, если их ещё нет в базе.

| Email | Пароль | Доступ |
| --- | --- | --- |
| `teacher@example.com` | `teacher` | Просмотр студентов и контактов |
| `admin@example.com` | `admin` | Просмотр, добавление, изменение контактов и удаление студентов |
| `superadmin@example.com` | `superAdmin` | Просмотр, создание и удаление пользователей |

Роли в исходном бэкенде не наследуются: суперадминистратор без дополнительной роли `ADMIN` или `TEACHER` не имеет доступа к студентам. Интерфейс учитывает это ограничение.

## Как проверить работу

1. Войти как преподаватель. Открыть студента: контакты доступны только для просмотра, кнопок добавления и удаления нет.
2. Выйти и войти как администратор. Добавить тестового студента, открыть его, изменить контакты и удалить запись.
3. Войти как суперадминистратор. Создать учебного пользователя с ролью преподавателя. Затем выйти и проверить вход под новым аккаунтом.
4. Перезагрузить страницу — действующий сеанс сохранится в текущей вкладке. Нажать «Выйти» — кабинет закроется.
5. Ввести неверный пароль или остановить бэкенд — появится сообщение об ошибке.

## Файлы проекта

| Файл | Назначение |
| --- | --- |
| `index.html` | Форма входа, таблицы и формы ввода |
| `src/main.js` | Обработчики кнопок и отображение данных |
| `src/api.js` | Запросы к бэкенду через `fetch` |
| `src/auth.js` | Сеанс, JWT и проверка ролей |
| `src/style.css` | Простое оформление страниц |
| `vite.config.js` | Локальный сервер и прокси к порту 8080 |

При создании студента API ожидает телефон в поле `phone_number`, при изменении — в `phoneNumber`. Обновление имени и фамилии в `StudentUpdateRequest` не предусмотрено, поэтому у существующего студента редактируются только контакты.

## Сборка

```bash
npm run build
```

Сборка создаётся в папке `dist`. Для проверки с API используйте `npm run dev`: обычная статическая раздача `dist` сама по себе не перенаправляет запросы к бэкенду.

GitHub содержит исходный код и инструкцию. Для работы приложения нужны запущенные бэкенд и PostgreSQL; загрузка в GitHub не запускает Java-сервер.

Сборка и программные проверки запросов выполнены. Совместный запуск с Spring Boot и PostgreSQL в среде разработки не проверен: зависимости Maven были недоступны. Сверка API выполнена по исходникам бэкенда, коммит `d4937296795b9b6586a538fc92ef2be92e9b2bac`.
