# Студенты — frontend

Фронтенд учебной информационной системы для [fun-student](https://github.com/dorzhogun/fun-student).

React + TypeScript + Vite. Интерфейс на русском языке, адаптирован для компьютеров и телефонов. Автор: Маслова Варвара.

## Возможности

- Вход по email и паролю через Spring Security; получение JWT от бэкенда.
- Авторизация по ролям `TEACHER`, `ADMIN`, `SUPER_ADMIN`.
- Сохранение сеанса в `sessionStorage`, восстановление при перезагрузке страницы, выход и автоматическое завершение сеанса при истечении токена или ответе 401.
- Список студентов, поиск по имени, фамилии и ID, локальная пагинация, карточка с контактами.
- Добавление и удаление студентов, изменение email и телефона для `ADMIN`.
- Список пользователей, поиск и фильтр по роли; создание аккаунтов, назначение ролей и удаление пользователей для `SUPER_ADMIN`.
- Состояния загрузки, пустого списка и ошибок; подтверждение удаления; валидация форм.
- Защита собственной учётной записи от удаления и изменения ролей через интерфейс.
- Страница «Мой доступ» с правами текущей учётной записи.

Публичной регистрации у исходного API нет. Учётные записи создаёт суперадминистратор на странице «Пользователи». Проверку паролей и подписи JWT выполняет сервер. Скрытие кнопок на фронтенде дополняет серверные ограничения, но не заменяет их.

## Быстрый запуск

Нужны Node.js 22.12+ (рекомендуется 24) и работающий бэкенд на Java 21 с PostgreSQL.

### 1. Запустить бэкенд преподавателя

```bash
git clone https://github.com/dorzhogun/fun-student.git
cd fun-student
```

В PostgreSQL создать базу `students_db`. По исходному `application.yml` сервер подключается к `localhost:5432`, пользователь `postgres`, пароль `postgres`, схема `students_schema`. Если ваша конфигурация другая, измените её в бэкенде. При необходимости до первого запуска выполните в базе `students_db`:

```sql
CREATE SCHEMA IF NOT EXISTS students_schema;
```

Запуск на macOS / Linux:

```bash
chmod +x mvnw
./mvnw spring-boot:run
```

На Windows:

```powershell
.\mvnw.cmd spring-boot:run
```

Дождитесь успешного запуска Spring Boot на порту `8080`.

### 2. Запустить фронтенд

Откройте терминал в корне **этого** репозитория:

```bash
npm ci
npm run dev
```

Откройте адрес, который напечатает Vite (обычно `http://localhost:5173`). Входить следует через страницу фронтенда, а не через порт 8080.

По умолчанию Vite перенаправляет `/api` на `http://localhost:8080`. Поэтому CORS-правки в исходном бэкенде для разработки не нужны.

При другом адресе бэкенда скопируйте `.env.example` в `.env` и задайте `BACKEND_URL`, затем перезапустите Vite. `.env` не коммитится.

## Учебные аккаунты

Эти аккаунты создаёт `AppInitializer` исходного бэкенда, если их ещё нет в базе. Данные ниже — публичные учебные значения из репозитория преподавателя, не личные пароли.

| Email                    | Пароль       | Права                                                         |
| ------------------------ | ------------ | ------------------------------------------------------------- |
| `teacher@example.com`    | `teacher`    | Просмотр списка и карточек студентов                          |
| `admin@example.com`      | `admin`      | Просмотр, добавление, изменение контактов, удаление студентов |
| `superadmin@example.com` | `superAdmin` | Управление учётными записями и ролями                         |

В исходном бэкенде **нет наследования ролей**: `SUPER_ADMIN` без `ADMIN` или `TEACHER` не имеет доступа к студентам. Фронтенд сохраняет это поведение. Можно назначить учётной записи несколько ролей.

## Демонстрация преподавателю

1. Войти как преподаватель: открыть список, найти студента и посмотреть контакты. Кнопки создания и удаления отсутствуют.
2. Выйти и войти как администратор: добавить тестового студента, открыть карточку и изменить контакты, затем удалить тестовую запись с подтверждением.
3. Войти как суперадминистратор: создать пользователя, назначить роли и проверить фильтр по ролям. Выйти и войти под новым пользователем.
4. Перезагрузить страницу: сеанс сохраняется в текущей вкладке. Нажать «Выйти»: кабинет закрывается.
5. Ввести неверные данные для входа или остановить бэкенд: появляется сообщение об ошибке.

Ссылка на GitHub показывает исходники и инструкцию. Для работы системы требуется запущенный бэкенд и PostgreSQL. GitHub Pages сам по себе не запускает Java и базу данных.

## Сборка и проверка

```bash
npm test
npm run build
```

`npm test` проверяет контракты запросов, сериализацию полей, права ролей, срок действия и восстановление сеанса, обработку ошибок. Тесты API используют подменённый `fetch`; они не подменяют проверку с реально запущенными Spring Boot и PostgreSQL.

`npm run build` проверяет TypeScript и создаёт `dist/`.

## Запуск собранного приложения

Для запуска сборки с прокси к уже работающему бэкенду можно использовать Docker:

```bash
docker compose up --build
```

Открыть `http://localhost:3000`. Контейнер nginx перенаправит `/api` к бэкенду на компьютере (`host.docker.internal:8080`). Если бэкенд находится на другом сервере, измените `BACKEND_URL` в `compose.yml`. Пароли и токены в переменные Vite не помещаются.

`npm run preview` служит для просмотра сборки и не включает dev-прокси Vite. Для полного взаимодействия с API используйте `npm run dev` или nginx из Docker.

Если фронтенд и API размещаются на разных HTTPS-доменах, при сборке задайте `VITE_API_URL=https://ваш-api-домен` **без** `/api/v1`, а на бэкенде настройте CORS для точного адреса фронтенда, методов `GET, POST, PUT, DELETE, OPTIONS` и заголовков `Authorization, Content-Type`. Проще использовать один домен с обратным прокси `/api`. Для размещения в подпапке задайте `VITE_BASE_PATH=/имя-репозитория/`.

## Контракт API

| Метод  | Путь                   | Роли           | Назначение                                                    |
| ------ | ---------------------- | -------------- | ------------------------------------------------------------- |
| POST   | `/api/v1/auth/login`   | Без входа      | Вход; `{email, password}` → `{token, type, expiresIn, roles}` |
| GET    | `/api/v1/student`      | ADMIN, TEACHER | Список в поле `response`                                      |
| GET    | `/api/v1/student/{id}` | ADMIN, TEACHER | Полные контакты                                               |
| POST   | `/api/v1/student/save` | ADMIN          | Создание; телефон в `phone_number`                            |
| PUT    | `/api/v1/student/{id}` | ADMIN          | Обновление; телефон в `phoneNumber`                           |
| DELETE | `/api/v1/student/{id}` | ADMIN          | Удаление                                                      |
| GET    | `/api/v1/users`        | SUPER_ADMIN    | Список в поле `responses`                                     |
| POST   | `/api/v1/users/save`   | SUPER_ADMIN    | Создание учётной записи                                       |
| PUT    | `/api/v1/users/{id}`   | SUPER_ADMIN    | Изменение ролей по текущему email                             |
| DELETE | `/api/v1/users/{id}`   | SUPER_ADMIN    | Удаление учётной записи                                       |

У всех защищённых запросов заголовок `Authorization: Bearer <token>`.

### Особенности исходного бэкенда

Совместимость сверена с коммитом `d4937296795b9b6586a538fc92ef2be92e9b2bac`.

- `StudentUpdateRequest` принимает только телефон и email, поэтому имя и фамилия существующего студента не редактируются.
- `UserServiceImpl.updateUser` ищет пользователя по email, изменяет роли, не меняет пароль и возвращает пустое тело. Интерфейс отправляет существующий email, после сохранения заново загружает список. Смена email и пароля через эту ручку не предлагается.
- В `SecurityConfiguration` нет CORS-конфигурации; локальный и nginx-прокси позволяют использовать бэкенд без изменений.
- Сервер использует учебные пароли и фиксированный JWT-ключ из исходников. Перед публичным использованием бэкенд требует отдельной настройки секретов и HTTPS.

## Структура

```text
src/
  App.tsx          — вход, кабинет, списки, карточки и формы
  api.ts           — запросы и обработка HTTP-ошибок
  auth.ts          — сеанс, срок действия JWT и права ролей
  types.ts         — типы данных API
  main.tsx         — точка входа
  style.css        — адаптивный интерфейс
  vite-env.d.ts    — типы переменных окружения
tests/
  contracts.test.ts — автоматические проверки
```

Приложение работает с данными API. В рабочий интерфейс не встроены фиктивные студенты и локальная имитация успешного входа.
