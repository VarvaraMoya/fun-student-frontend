# Учёт студентов

Веб-приложение для работы со студентами и учётными записями. Интерфейс написан на HTML, CSS и JavaScript и использует REST API [fun-student](https://github.com/dorzhogun/fun-student).

## Возможности

- Вход по email и паролю, выход из системы.
- Аутентификация через JWT и авторизация по ролям.
- Сохранение сеанса при обновлении страницы в текущей вкладке.
- Просмотр списка студентов и контактной информации.
- Добавление, изменение контактов и удаление студентов.
- Создание и удаление учётных записей пользователей.

Доступ к функциям определяется ролью. Пароль и JWT проверяются сервером. Создание учётных записей доступно суперадминистратору; публичной регистрации нет.

## Технологии

- HTML — разметка страницы и форм.
- CSS — оформление и адаптация для небольших экранов.
- JavaScript — обработчики событий, работа с сеансом и запросы `fetch`.
- Vite — локальный сервер и сборка приложения.

## Запуск

Требуются Node.js 22.12 или новее, Java 21 и PostgreSQL.

### 1. База данных

В PostgreSQL создать базу:

```sql
CREATE DATABASE students_db;
```

Подключиться к `students_db` и создать схему:

```sql
CREATE SCHEMA IF NOT EXISTS students_schema;
```

Параметры подключения по умолчанию: `localhost:5432`, пользователь `postgres`, пароль `postgres`. Если используются другие параметры, их нужно указать в `src/main/resources/application.yml` бэкенда.

### 2. Бэкенд

```bash
git clone https://github.com/dorzhogun/fun-student.git
cd fun-student
```

На macOS и Linux:

```bash
chmod +x mvnw
./mvnw spring-boot:run
```

На Windows:

```powershell
.\mvnw.cmd spring-boot:run
```

Сервер должен запуститься на `http://localhost:8080`.

### 3. Фронтенд

В другом терминале:

```bash
git clone https://github.com/VarvaraMoya/fun-student-frontend.git
cd fun-student-frontend
npm ci
npm run dev
```

Открыть адрес, который напечатает Vite, обычно `http://localhost:5173`.

Запросы `/api` перенаправляются на `http://localhost:8080`. При другом адресе API скопировать `.env.example` в `.env`, изменить `BACKEND_URL` и перезапустить Vite.

## Учётные записи

При первом запуске бэкенд создаёт следующие аккаунты, если их ещё нет в базе:

| Email | Пароль | Роль | Доступ |
| --- | --- | --- | --- |
| `teacher@example.com` | `teacher` | `TEACHER` | Просмотр студентов и контактов |
| `admin@example.com` | `admin` | `ADMIN` | Просмотр, добавление, изменение контактов и удаление студентов |
| `superadmin@example.com` | `superAdmin` | `SUPER_ADMIN` | Просмотр, создание и удаление пользователей |

Роли не наследуются: `SUPER_ADMIN` без дополнительной роли `ADMIN` или `TEACHER` не получает доступ к студентам.

| --- | --- |
| `index.html` | Форма входа, таблицы и формы ввода |

| `vite.config.js` | Настройка сервера и прокси к API |

## Работа с API

При входе отправляется `POST /api/v1/auth/login` с email и паролем. Полученный токен передаётся в защищённых запросах в заголовке `Authorization: Bearer <token>`.

При создании студента телефон передаётся в поле `phone_number`, при изменении — в `phoneNumber`. Бэкенд позволяет изменять только email и телефон существующего студента.

При истечении сеанса или ответе `401` приложение возвращается к форме входа. Ответ `403` означает, что текущей роли недостаточно прав.

## Сборка

```bash
npm run build
```

Результат находится в `dist`. Для локальной работы с API используется `npm run dev`. При размещении собранной версии на сервере необходимо настроить перенаправление `/api` к бэкенду.

## Проверка работы

1. Войти под `TEACHER`, открыть список и карточку студента. Изменение данных недоступно.
2. Войти под `ADMIN`, добавить запись, изменить её контакты и удалить её.
3. Войти под `SUPER_ADMIN`, создать пользователя и проверить вход с его данными.
4. Перезагрузить страницу, затем выйти из системы.
5. Проверить неверный пароль и обращение без достаточных прав.

Проверено совместно с Spring Boot 4.0.8 и PostgreSQL 18.6: вход трёх ролей, ограничения доступа, создание и изменение студента, удаление записей, создание пользователя и вход с его данными. Также проверены сохранение сеанса после обновления страницы, выход и сообщение о неверном пароле. Запросы выполнялись через прокси Vite; сценарии с формами пройдены в браузере.
